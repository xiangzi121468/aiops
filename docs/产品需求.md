# 产品需求文档：进化型 AI 平台

## 1. 项目概述
本项目旨在构建一个双阶段 AI 平台：初期作为**个人知识与技术助手（第一阶段）**，随后演进为具备自主能力的**AIOps 运维工程师 Agent（第二阶段）**。

**优先目标用户与路径**：
- 目标用户优先级：运维场景的检索 + 诊断优先，但必须先具备“个人知识助手”的知识库能力作为基础。
- 推进路径：先完成基础知识库与检索能力，再拓展到监控/日志/告警驱动的运维诊断与处置建议。

## 2. 第一阶段：智慧大脑
**目标**：解决开发者的“信息孤岛”与“上下文丢失”问题。

| ID | 功能 | 描述 | 价值 |
| :--- | :--- | :--- | :--- |
| **1.1** | **多源 RAG** | 采集代码（AST 友好）、Markdown（Obsidian 链接）与网页 URL。 | “第二大脑”式召回。 |
| **1.2** | **混合记忆** | **语义记忆**：基于 SQL 的用户画像（如“偏好 Python”）。<br>**情节记忆**：向量召回历史对话。 | 个性化、上下文更准确。 |
| **1.3** | **知识园丁** | 后台去重、合并与更新过期知识。 | 维持知识库健康。 |
| **1.4** | **架构审计** | 用过往失败（Post-Mortem）校验新代码/设计。 | 预防性风险识别。 |

## 3. 第二阶段：AIOps 神经系统
**目标**：打通“监控发现”到“故障修复”的闭环。

| ID | 模块 | 集成 | 工作流 |
| :--- | :--- | :--- | :--- |
| **2.1** | **传感器（Eyes）** | **Prometheus**：AlertManager Webhook。<br>**Logs**：ELK / Loki API。 | “告警触发 -> 查询日志 -> AI 诊断” |
| **2.2** | **执行器（Hands）** | **Kubernetes/EKS**：Pod/Deployment 控制。<br>**SSH/Shell**：安全命令执行。 | “诊断 -> 建议修复 -> 人工审批 -> 执行” |
| **2.3** | **基础设施（IaC）** | **Terraform**：阿里云 / AWS Provider。 | “需求 -> 生成 TF -> 审计 -> Apply” |

## 4. 自学习闭环（核心差异化）
系统通过每次事件持续进化：
1. **事件解决**：用户标记故障“已解决”。
2. **自动复盘**：汇总日志、对话与操作生成复盘文档。
3. **回写知识库**：案例入库并可检索。
4. **未来影响**：架构审计优先命中相似模式并提示风险。

## 5. 交互界面
* **Chat 模式**：常规对话 UI，用于查询与协助。
* **War Room（作战室）**：事故模式双栏视图。
  * 左侧：实时日志流与指标图表。
  * 右侧：AI Copilot 实时分析。

## 6. 非功能需求
* **安全**：高风险操作必须“人机回环”（审批）。
* **技术栈**：FastAPI（后端）、React（前端）、LangGraph（编排）、ChromaDB（向量）、SQLite（关系型）。
* **审批与风控**：
  * **高风险操作清单**：重启/扩缩容/回滚/配置变更/删除与高权限命令。
  * **审批机制**：审批人角色 + 责任人（Owner）双重确认；支持多级审批。
  * **SLA**：审批超时（如 5 分钟）自动回退到只读/只检索模式，并记录原因。
  * **审计字段**：操作类型、发起人、审批人、结果、时间、关联工单/事件 ID。

## 7. 需求优化补充（范围与指标）
*   **用户画像与角色**：开发者/运维/管理者的典型场景、权限与优先级差异。
*   **可衡量指标**（目标值可调整）：
    * **Top‑K 命中率**：>= 0.75（基准集）
    * **P95 检索延迟**：<= 2.5s（基础检索）
    * **MTTD 改善**：>= 30%
    * **MTTR 改善**：>= 20%
    * **误报/漏报率**：<= 5%
*   **数据与合规**：敏感数据分类、脱敏规则、审计保留时长、合规标准。
*   **数据源边界**：
    * **监控/告警**：Prometheus / AlertManager（指标 + 告警）
      - 现阶段：Prometheus 未接入，需完成 AlertManager Webhook 接入
      - 告警窗口：支持 15/30/60 分钟区间拉取（可配置）
    * **日志中心**：Loki + ELK（结构化日志 + 关键日志片段）
      - 现阶段：两者都接入，查询范围可配置
      - **日志查询策略**：
        - 触发方式：告警驱动 + 用户主动查询
        - 默认范围：关联服务 + 命名空间 + 告警窗口
        - 采样上限：单次 200-500 行（可配置）
        - 关键词优先：ERROR / Exception / timeout / panic
        - 超时策略：单次查询超时 5s（可配置），返回部分结果
        - 脱敏：对 token / 密钥 / 用户敏感字段做脱敏
        - 以上策略与默认值均可配置
    * **变更事件**：CI/CD 发布记录、配置变更记录
    * **拓扑来源**：CMDB / Service Map（可选）
    * **采集方式**：Webhook + Pull；采集频率与保留策略可配置
    * **白名单**：数据源类型/租户/命名空间/项目级白名单
    * **存储策略**：后续支持落库保存（事件级与查询结果可配置）
*   **记忆生命周期**：巩固/强化/遗忘/过期/权重衰减触发条件。
*   **知识来源边界**：支持的文件类型、大小限制、URL 采集策略与增量更新。
*   **多租户隔离**：租户/项目级隔离与共享知识授权策略。
*   **错误与降级**：工具调用失败、检索为空、异常降级策略。
*   **安全策略细化**：高风险操作清单、审批 SLA、审批失败处理。
*   **性能与成本**：检索延迟目标、向量规模上限、Embedding 成本估算。
*   **可观测性**：日志/指标/追踪规范与可视化要求。

## 8. 验收标准（可执行）
*   **用户画像与角色**：至少 3 类角色可配置权限与可见范围；角色切换无越权访问。
*   **可衡量指标**：支持配置与导出指标；P95 检索延迟、Top‑K 命中率可统计。
*   **数据与合规**：提供脱敏规则清单与审计日志留存配置；支持按时间/类型查询审计。
*   **数据源边界**：接入 Prometheus/AlertManager 与日志中心 Loki + ELK；支持 15/30/60 分钟告警窗口与范围配置。
*   **日志查询策略**：支持告警驱动与主动查询；支持采样上限与超时策略；关键词优先检索与脱敏输出。
*   **记忆生命周期**：支持配置过期与权重衰减策略；过期数据不可被检索命中。
*   **知识来源边界**：支持配置允许的文件类型/大小/来源；超限拒绝并给出提示。
*   **多租户隔离**：跨租户检索不可见；共享知识需显式授权。
*   **错误与降级**：工具失败可回退到只读/只检索模式；返回明确错误原因。
*   **安全策略细化**：高风险操作必须审批；审批超时有明确的回退策略。
*   **性能与成本**：检索延迟目标可配置；支持基础成本统计（Embedding 调用次数）。
*   **可观测性**：提供关键链路日志与指标；支持按事件追踪问题处理流程。

## 9. 测试用例（建议）
*   **角色与权限**：不同角色访问相同资源，验证可见范围与禁止项。
*   **检索命中率**：给定标准问题集，评估 Top-K 命中率与平均延迟。
*   **脱敏与审计**：写入含敏感字段的数据，验证脱敏生效与审计可追溯。
*   **记忆过期**：配置过期策略后，验证过期记忆不可检索。
*   **多租户隔离**：跨租户检索请求返回为空或拒绝。
*   **异常降级**：模拟向量库/工具调用失败，验证降级路径。
*   **审批流程**：高风险操作触发审批，超时回退策略生效。
*   **性能基线**：在指定数据规模下测量检索耗时与吞吐。

## 10. 实施任务清单（建议）
*   **角色与权限**：设计 RBAC 模型与权限矩阵；实现鉴权中间件。
*   **指标体系**：定义核心指标与计算方式；落地仪表盘与导出接口。
*   **合规与审计**：设计审计表结构；实现脱敏与日志写入。
*   **记忆生命周期**：实现过期与衰减调度；提供配置入口。
*   **知识边界**：实现文件类型/大小/来源白名单校验。
*   **多租户隔离**：实现租户级命名空间与检索过滤。
*   **降级策略**：设计故障回退与告警；实现可观测性埋点。
*   **审批机制**：实现审批流与超时策略；记录审批结果。
*   **性能优化**：向量库索引策略与缓存；压测与容量规划。
