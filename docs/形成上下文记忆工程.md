# 形成上下文记忆工程

本文档将“短期记忆 + 长期记忆 + 检索 + 写回”的通用模式，落到本项目的工程化设计与实现步骤上。

## 目标与原则
- 可检索：高命中、低噪声
- 可解释：能追溯来源与上下文
- 可控：可清理、可过期、可权限隔离
- 可成长：自学习闭环持续增强

## 概念对齐（与项目架构）
- 短期记忆（Session）：当前会话上下文，直接参与推理，受 token 限制。
- 长期记忆（Long-term）：
  - 情节记忆（Episodic）：对话片段、案例复盘，存向量库。
  - 语义记忆（Semantic）：稳定事实与偏好，存关系库。
- 检索（Retrieve）：RAG 并行召回知识记忆 + 情节记忆。
- 写回（Record）：异步提炼与入库（Profilling / Summarizer）。

## 系统分层
1. 工作记忆（Working）
   - 来源：最近 N 轮对话、当前工具调用结果
   - 存储：内存或 Redis
   - 生命周期：会话级
2. 情节记忆（Episodic / Vector）
   - 来源：对话摘要、问题-解决链、案例复盘
   - 存储：ChromaDB
   - 作用：相似问题召回
3. 语义记忆（Semantic / SQL）
   - 来源：用户偏好与稳定事实
   - 存储：SQLite
   - 作用：个性化回答与策略纠偏
4. 知识记忆（Knowledge / Vector）
   - 来源：代码、文档、网页
   - 存储：ChromaDB
   - 作用：RAG 主检索源

## 读写流程（时序）
1. 用户输入进入工作记忆
2. 检索并行召回：
   - 知识记忆（kb_chunks）
   - 情节记忆（memory_chunks）
3. 形成最终上下文 -> LLM 推理 + 工具调用
4. 生成回复
5. 异步写回：
   - 事实/偏好 -> 语义记忆（SQL）
   - 案例/对话摘要 -> 情节记忆（向量库）

## 上下文处理核心策略（对齐图示）
### 1) 编减（Reduction）
- 目标：在 token 受限下压缩上下文，保留关键事实。
- 工程化方式：
  - 摘要：对长对话进行分段摘要，保留问题/结论/关键参数。
  - 关键信息抽取：保留错误码、版本、依赖、环境、配置变更等。
  - 结构化压缩：输出为固定模板字段，方便后续检索。

### 2) 卸载（Offloading）
- 目标：将历史对话或大文档“外部化存储”，按需召回。
- 工程化方式：
  - 对话记录 -> 向量库（情节记忆）
  - 文档/代码 -> 向量库（知识记忆）
  - 仅把检索命中片段拼回当前上下文

### 3) 隔离（Isolation）
- 目标：避免不同任务/子智能体互相污染上下文。
- 工程化方式：
  - Session/Task 维度隔离 memory namespace
  - 以 case_id / session_id 为过滤条件
  - 高风险工具调用结果不默认写入全局记忆

## LangChain 中间件示例（与短期记忆存储解耦）
下例展示通过 `SummarizationMiddleware` 设置上下文处理参数，并与短期记忆存储解耦：

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="gpt-4o",
    tools=[...],
    middleware=[
        SummarizationMiddleware(
            model="gpt-4o-mini",
            max_tokens_before_summary=4000,  # 4000 tokens时触发摘要
            messages_to_keep=20,  # 摘要后保留最后20条消息
        ),
    ],
)
```

## 上下文选择原则（对齐图示）
1. 时间靠近：优先保留最新上下文（最近 N 轮）
2. 数据类型：任务相关 > 工具结果 > 闲聊
3. 可恢复性：
   - 可恢复（可从存储/检索得到）：优先卸载
   - 不可恢复（一次性上下文）：优先编减保留

## 策略与架构对齐关系
- 编减 -> Session Memory 与摘要器（summary reducer）
- 卸载 -> ChromaDB 向量库（kb_chunks / memory_chunks）
- 隔离 -> 会话/任务级 namespace + 权限标签

## 数据模型建议
### 语义记忆（SQL）
- user_profile(id, key, value, confidence, source, updated_at)
- user_preference(user_id, topic, value, weight)
- action_log(user_id, action, tool, result, ts)

### 情节记忆（向量）
- memory_chunks(id, content, embedding, metadata)
  - metadata: source, session_id, timestamp, tags, case_id

### 知识记忆（向量）
- kb_chunks(id, source_type, path_or_url, content, embedding, metadata)
  - metadata: repo, file_path, section, version

## 长期记忆技术架构（Record & Retrieve）
长期记忆的核心流程是 record 与 retrieve，涉及以下组件：
1. LLM 大模型：从短期记忆中提取有效信息（语义理解、抽取、决策、生成）。
2. Embedder 向量化：将文本转换为语义向量，支持相似度计算。
3. VectorStore 向量数据库：持久化存储记忆向量与元数据，支持高效检索。
4. GraphStore 图数据库：存储实体-关系知识图谱，支持复杂关系推理。
5. Reranker（重排序器）：对初步检索结果按语义相关性重新排序。
6. SQLite：记录记忆操作审计日志，支持版本回溯。

## Record & Retrieve 流程
### Record（记录）
1. LLM 事实提取
2. 信息向量化
3. 向量存储
4. 复杂关系存储（Graph）
5. SQLite 操作日志

### Retrieve（检索）
1. User query 向量化
2. 向量数据库语义检索
3. 图数据库关系补充
4. Reranker/LLM 重排序
5. 结果返回

## 写回策略（控制噪声）
- 仅写“稳定事实 / 完整案例”
- 低置信度不入库（confidence 阈值）
- 记忆衰减：时间加权衰减，不强删

## 安全与权限
- 每条记忆带 visibility 与 owner
- 入库前敏感信息脱敏
- 支持按来源、时间、类型清理

## MVP 实施优先级
1. Session Memory + 检索读取（Retrieve 打通）
2. 异步写回（Record 基础版）
3. 画像提炼（Passive Profiler -> SQL）
4. Case Summarizer（自学习闭环）

## 行业优化与长期记忆演进
现有框架内置的压缩、卸载、摘要等策略，已能覆盖 80-90% 的通用场景。但在医疗、法律、金融等高专业领域，仍需要在通用策略基础上进行更细粒度的上下文处理与压缩 prompt 设计，留有显著优化空间。

长期记忆应作为可独立演进的组件，逐步贴近人脑的记忆演化模式，包括记忆的巩固、强化、遗忘等全生命周期管理。同时长期记忆可作为云服务形态提供通用记忆能力，持续支撑 Agent 迈向更高阶智能。

## K8s / DevOps / 监控告警 场景上下文模板
以下字段用于面向运维场景的上下文编减与摘要模板，建议以结构化形式输出：

1. **基础元信息（Meta）**：集群/环境/租户/业务线/时间窗口
2. **系统与资源上下文（Context）**：命名空间、节点、工作负载、资源配额
3. **监控指标（Metrics）**：CPU/内存/磁盘/网络/延迟/错误率
4. **日志信息（Logs）**：关键日志片段、异常堆栈、错误码
5. **事件与告警（Events & Alerts）**：告警名称、级别、触发条件、持续时间
6. **变更与发布（Change）**：部署版本、配置变更、发布人、时间点
7. **拓扑与依赖（Topology）**：上下游服务、依赖资源、调用链路
8. **异常分析结果（AI Analysis）**：根因假设、关联证据、置信度
9. **处置建议与自动化动作（Action）**：建议步骤、自动化脚本、回滚方案
10. **结果回溯与学习（Feedback）**：处理结果、验证指标、经验沉淀
